# 관리자 이의 처리 운영 정책

관련 요구사항: `FR-35~40`, `FR-50~54`, `TR-01~03`

이 문서는 사용자의 명시적인 요청에 따라 기존 P0 정산 경계에 추가한, 수동
관리자 처리 권한을 기록한다. 자동 정산을 추가하지 않는다.

## 권한과 조치

활성 `ADMIN`만 현재 `SETTLEMENT_PENDING` 상태의 실제 요금 이의를 처리할 수
있다. 처리 사유와 멱등성 키는 필수이며 모든 처리는 감사 기록으로 남는다.

- **기각:** 이의만 `REJECTED`로 종결한다. 실제 요금, 확인, 예치금, 원장은
  변경하지 않는다.
- **금액 수정:** 다른 열린 이의가 없을 때 관리자에게 입력한 양의 실제 요금으로
  새 요금 차수를 만든다. 예치 확정 cohort(노쇼 포함)는 바꾸지 않고, 기존
  확인을 초기화해 새 24시간 확인 기한을 시작한다. 이 단계에서는 원장을 쓰지
  않는다.
- **강제 정산:** 다른 열린 이의가 없고 처리 대상이 마지막 열린 이의일 때,
  관리자는 현재 요금 차수로 최종 정산할 수 있다. 참여자 확인과 기한을
  건너뛸 수 있지만, 모든 cohort의 추가 차감 가능 잔액을 먼저 검증한다.
  부족하면 전체 트랜잭션이 롤백된다.

금액 수정과 강제 정산은 하나의 명령으로 결합하지 않는다. 강제 정산은
`ESCROW_CONFIRMED` cohort 전체를 사용하며 `NO_SHOW`를 제외하거나 재분할하지
않는다. 원장, 참여자 완료, 정산 완료, 모집 완료는 하나의 SERIALIZABLE
트랜잭션에서 함께 기록한다. 완료된 정산의 수정은 지원하지 않는다.

## 감사 기록

`admin_dispute_commands`는 관리자 금액 수정과 강제 정산의 이전/수정 금액,
요금 차수, 정산 인원, 확인 수와 기한, 사유, 관리자, 멱등성 키를 append-only로
보존한다. 일반 기각은 기존 `fare_disputes`의 해결자·사유·멱등성 기록으로
감사한다.
