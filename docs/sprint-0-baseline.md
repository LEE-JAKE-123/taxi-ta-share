- 기준일: 2026-07-30
- 기준 문서: `docs/prd.md` v0.7, `AGENTS.md`
- 상태: 기술 기준선 확정, 사업·운영 정책 결정 대기

## 1. MVP 요구사항 기준

`docs/prd.md`의 Must 요구사항과 `TR-01~08`을 구현·출시 판단의 기준으로
사용한다. Should 요구사항은 구현, 이월 또는 제외 사유를 출시 전에
`docs/sprint-plan.md`에 기록한다.

MVP에서 제외한다.

- 실제 카드 결제와 PG 연동
- 사용자 직접 포인트 충전
- 현금 인출과 사용자 간 포인트 송금
- 자연어 모델이 생성한 목적지, 거리, 시간 또는 요금
- 결정되지 않은 취소 수수료, 노쇼 추가 제재와 자동 분쟁 판정

Mock 데이터는 화면 표현에만 사용할 수 있다. 권한, 모집·참여 상태, 포인트,
정산과 추천 근거의 권위 데이터로 사용할 수 없다.

## 2. 모집·참여 상태 기준

### 모집 전이

| 현재 | 사건/주체 | 선행 조건 | 다음 | 실패·재시도 |
|---|---|---|---|---|
| DRAFT | 게시/방장 | 필수 입력과 가입 정보 완료 | OPEN | DRAFT 저장·게시 UX는 미결이므로 현재 영속화하지 않음 |
| OPEN | 수동 종료/방장 | 출발 전, 확정 인원 2~4명 | CLOSED | 비방장·종료 상태 거부, 같은 키 재시도는 동일 결과 |
| OPEN | 수동 종료/방장 | 출발 전, 확정 인원 2명 미만 | EXPIRED | 동일 |
| OPEN | 자동 종료/시스템 | 출발 시각 도래, 확정 인원 2~4명 | CLOSED | 모집 행 잠금 후 한 번만 전이 |
| OPEN | 자동 종료/시스템 | 출발 시각 도래, 확정 인원 2명 미만 | EXPIRED | 동일 |
| OPEN | 전체 취소/방장 | 출발 전, 확정 참여자·예치 없음 | CANCELLED | 확정 참여자가 있으면 정책 결정 전 차단 |
| CLOSED | 확정·예치/방장 | 출발 전, 2~4명, 요금 산정, 참여자별 가용 포인트 예치와 필요한 예치 부족분 기록 | CONFIRMED | 상태·예치·부족분·원장을 한 트랜잭션으로 처리 |
| CONFIRMED | 이동 시작/권한 주체 | 집결·노쇼 선행 조건 충족 | IN_PROGRESS | 권한 주체와 집결 증빙 정책 미결 |
| IN_PROGRESS | 실제 요금 제출/권한 주체 | 실제 이동 완료 | SETTLEMENT_PENDING | 제출 멱등성 보장 |
| SETTLEMENT_PENDING | 잠정 정산/시스템 | 전원 동의 또는 실제 요금 등록 후 10분 동의 기한 만료 | SETTLEMENT_PENDING | 잠정 원장·상태를 한 트랜잭션으로 처리 |
| SETTLEMENT_PENDING | 최종 완료/시스템 | 실제 요금 등록 후 24시간 이의 기한 만료 및 모든 이의 처리 | COMPLETED | 금액·상태·원장을 한 트랜잭션으로 처리 |

`CLOSED`, `EXPIRED`, `CANCELLED` 이후에는 신규 신청과 승인을 허용하지 않는다.
출발 시각 이후에는 `CLOSED` 모집을 예치 확정할 수 없다. 출발 전 예치 확정을
끝내지 못한 모집은 `EXPIRED`가 되고, 이미 보류한 포인트는 멱등적으로 반환한다.
`DRAFT`는 PRD 상태지만 임시 저장·게시 UX가 정해지지 않아 Sprint 2 완료 범위에서
열린 결정으로 유지한다.

### 참여자 전이

| 현재 | 사건 | 다음 | 핵심 조건 |
|---|---|---|---|
| 없음 | 참여 신청 | APPLIED | 사용자 정보 완료, 모집 OPEN·출발 전 |
| APPLIED | 방장 승인 | APPROVED | 모집 OPEN·출발 전, 최대 4명 |
| APPROVED | 예치 | DEPOSITED | 모집 CLOSED, 가용 포인트 예치와 필요한 참여자별 예치 부족분 기록 |
| DEPOSITED | 집결 확인 | CHECKED_IN | 권한·집결 정책 필요 |
| DEPOSITED | 미도착 판정 | NO_SHOW | 증빙·판정 주체 정책 필요 |
| DEPOSITED/NO_SHOW | 요금 이의 | 참여자 상태 유지 | Settlement/Dispute 기록으로만 추적하며 최종 완료를 보류 |
| DEPOSITED/CHECKED_IN/NO_SHOW | 정산 완료 | COMPLETED | 확정 인원 기준 정산 |
| APPLIED/APPROVED | 참여 취소 | CANCELLED | `OPEN`·출발 전·예치 전만 가능. 모집 종료 또는 예치 후에는 취소 불가이며 확정 인원은 정산 대상으로 유지 |

모집 상태와 참여자 상태는 같은 서버 트랜잭션 경계에서 함께 검증한다.
집결 시각 미도착 또는 노쇼 신고는 귀책의 자동 확정이 아니다. 추가 차감·이용
제한에는 서버 기록, 허용된 증빙, 반박 기회와 운영자 또는 사전 정의된 서버 규칙의
판정이 필요하다. `HOST_NO_START` 책임이 확정된 경우에만 관리자가 별도 명령으로
모집을 `CANCELLED`로 전이하고 비귀책 `MEMBER`의 예치금만 전액 반환한다.

## 3. 포인트·정산 불변식

- 포인트는 관리자만 지급하는 가상 단위이며 구매·환전·출금할 수 없다.
- 원장은 append-only이고 지급·예치·반환·추가 차감을 모두 기록한다.
- 일반 잔액과 예치 잔액은 분리하며 음수가 될 수 없다.
- 예상 예치액은 `D = ceil(E/N)`을 사용한다. 실제 총요금 `A`의 개인 부담액은
  방장·승인 시각·사용자 ID 순서의 결정적 배분으로 합계가 항상 `A`가 되도록
  계산하며, 배분 결과는 정산 스냅샷에 보존한다.
- 상태 변경과 원장 기록은 하나의 DB 트랜잭션에서 처리한다.
- 멱등성 키는 DB 유일성 제약으로 보강한다.
- 정산 인원 `N`은 확정 시 확정 참여자 집합으로 고정한다. 노쇼 상태로
  바뀌어도 `N`과 대상 집합에서 제외하지 않는다.
- 참여자별 예치 부족분은 현재 모집의 `CONFIRMED`·집결·이동을 막지 않지만,
  그 사용자의 다른 모집 생성·신청·예치는 막는다. 실제 요금 잠정 정산에서만
  해당 참여자별로 상계하며, 이중 청구하거나 다른 참여자에게 재배분하지 않는다.
- 확정·예치 이후 전체 취소는 반환·수수료 정책이 결정되기 전 실행하지 않는다.
- 전원 동의 또는 실제 요금 등록 후 10분 동의 기한 만료 시 시스템은 잠정 정산을
  실행한다. 열린 이의가 있으면 최종 완료를 실행하지 않으며, 실제 요금 등록 후
  24시간 이의 기한이 끝나고 모든 이의가 처리된 뒤에만 최종 완료한다.

## 4. 지도·추천 기준

제공자 선정 전에도 다음 경계는 고정한다.

- 장소 검색, 지오코딩, 경로, 거리·시간과 요금 산정을 제공자 중립 인터페이스
  뒤에 둔다.
- 좌표계, m/km, 초/분, 정수 포인트, 반올림, 산정 시각과 오류 코드를 경계에서
  정규화한다.
- 추천은 실제 OPEN 후보와 저장된 계산 근거만 사용한다.
- 후보 ID와 revision, 경로·요금 calculation ID, 거리·시간·요금 출처,
  산정·만료 시각, 정책 버전·임계값, 결정적 rank key와 추천 문구 입력을 추적한다.
- 추천 문구는 결정적 계산 결과로 만들고 자동 참여·확정을 수행하지 않는다.
- 시간 초과, 제한, 캐시 노후화, 경로 없음과 제공자 장애를 명시적으로 처리한다.

지도 제공자는 카카오맵으로 선택했다. 자격 증명과 API 상품, 택시 요금
산식·할증은 `DEC-003`, 인접 목적지 우회 한도는 `DEC-005`의 남은
결정이며 해당 연동 구현의 차단 항목이다.

## 5. 환경·보안 기준

- Development, Preview, Production은 서로 다른 Neon 브랜치 또는 프로젝트,
  fingerprint와 자격 증명을 사용한다.
- 런타임은 pooled 최소 권한 연결, 마이그레이션은 승인된 direct 연결을 사용한다.
- 비밀값은 로컬 비추적 환경 파일 또는 Vercel 환경 변수에만 저장한다.
- 가입·세션·관리자 권한과 모든 도메인 입력은 서버에서 재검증한다.
- 정확한 거주지, 연락처와 불필요한 위치정보를 다른 사용자에게 노출하지 않는다.

현재 로컬 Development 설정이 Production fingerprint를 가리켜 검증이 차단되므로
별도 개발 Neon 연결 전에는 로컬 마이그레이션을 실행하지 않는다.

## 6. 테스트 계층과 품질 게이트

| 계층 | 범위 | 필수 증거 |
|---|---|---|
| 단위 | 입력, 금액 계산, 상태 판정, 제공자 정규화 | 경계값과 실패 케이스 |
| DB 통합 | 제약, 트랜잭션, 멱등성, 동시 요청 | 격리된 Development/Preview DB |
| 애플리케이션 통합 | Server Action, 인증·권한, 오류 복구 | 실제 DB 세션 |
| E2E | 가입→생성→참여→예치→이동→정산 | Preview 환경 모바일 뷰포트 |

모든 변경은 최소한 `pnpm lint`, `pnpm exec tsc --noEmit`, 관련 테스트,
`pnpm build`를 통과해야 한다. DB 변경은 migration checksum, 환경 fingerprint,
전진 적용과 보상 절차를 검증한다. 운영 데이터용 자동 seed는 금지하고 테스트
fixture는 격리 DB에서만 생성·정리한다.

CI 품질 게이트는 위 네 명령, 비밀값 검사와 migration drift 검사를 필수로 한다.
현재 저장소에 CI 워크플로가 없어 실제 자동화는 후속 작업이다.

## 7. 미결 정책과 책임

다음 항목은 구현자가 결정할 수 없다. 구체적인 담당자와 결정 기한 지정이
필요하다.

- Neon 리전, Preview/Production 분리, 백업 보유, RPO/RTO, 복구 훈련과 경보
- 지도 제공자, 요금 산식·할증, 인접 목적지 우회·경유 동의
- 관리자 초기 포인트 지급액·회수
- 취소 수수료·반환, 노쇼 추가 수수료·반복 제재
- 집결·노쇼·분쟁 증빙과 운영자 판정
- 개인정보·위치정보·가상 포인트 운영의 법률·정책 검토 책임자

담당자가 지정되지 않은 항목은 `docs/sprint-plan.md`에서 `Blocked`로 유지한다.
