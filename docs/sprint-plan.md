# TaxiTaShare MVP 스프린트 개발 계획

- 문서 상태: Active
- 기준 문서: `docs/prd.md` v0.7, `AGENTS.md`
- 최초 작성일: 2026-07-29
- 최종 갱신일: 2026-07-30
- 계획 단위: 2주 스프린트(팀 상황에 따라 기간만 조정 가능)
- MVP 목표: 1개 대학 또는 1개 캠퍼스 파일럿

## 1. 문서 사용법

이 문서는 개발 순서, 요구사항 추적, 완료 증거를 한곳에서 관리하는 실행 문서다. 기능을 완료했다는 이유만으로 체크하지 않고, 해당 항목의 수용 기준과 검증이 모두 끝났을 때만 `[x]`로 변경한다.

### 1.1 체크 상태

- `[ ]`: 미착수
- `[~]`: 진행 중
- `[x]`: 완료 및 검증됨
- `[!]`: 차단됨. 같은 줄 또는 스프린트 기록에 원인과 필요한 결정을 남긴다.
- `[-]`: 범위 제외. 제외 사유와 승인자를 결정 로그에 남긴다.

> GitHub 체크박스는 `[ ]`와 `[x]`만 렌더링한다. `[~]`, `[!]`, `[-]`는 운영용 텍스트 상태다.

### 1.2 업데이트 규칙

1. 스프린트 시작 시 목표, 담당, 대상 FR/TR, 선행 조건을 확정한다.
2. 작업 시작 시 해당 항목을 `[~]`로 바꾸고 아래 실행 기록에 날짜를 남긴다.
3. PR 또는 작업 단위마다 관련 FR/TR ID를 제목과 완료 보고에 기록한다.
4. 코드 완료 후 수용 기준, 경계값 테스트, `pnpm lint`, `pnpm exec tsc --noEmit`, `pnpm build` 중 적용 가능한 검증을 실행한다.
5. 검증 증거가 있는 항목만 `[x]`로 바꾼다. 실행하지 않은 검증은 완료로 기록하지 않는다.
6. 정책 미결로 구현할 수 없는 항목은 `[!]`로 바꾸고 결정 로그에 등록한다.
7. 스프린트 종료 시 완료/이월/차단 항목과 회고를 기록하고, 요구사항 추적표의 상태도 함께 갱신한다.
8. PRD가 변경되면 문서 상단 기준 버전과 변경 이력을 갱신하고 영향받는 체크를 재검토한다.

### 1.3 완료 증거 형식

각 완료 항목에는 실행 기록 또는 PR 설명에 다음을 남긴다.

```text
날짜:
항목:
관련 요구사항:
변경 파일/PR:
검증 명령 및 결과:
경계·실패 시나리오:
남은 위험/결정:
```
